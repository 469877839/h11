Add a ``line_ending_policy`` argument to :class:`Connection` to choose how received line terminators are parsed. The default :data:`h11.LENIENT` keeps the historical behavior of accepting both CRLF and bare LF, while :data:`h11.STRICT` requires CRLF for the request/status line, header lines, chunk size lines, chunk terminators, and trailers, raising :exc:`RemoteProtocolError` on a bare LF. Message-body bytes are not affected, and data sent by h11 still always uses CRLF.
